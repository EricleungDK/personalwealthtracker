Plain English

What has been achieved so far

The project has turned a manual monthly finance chore into a careful assistant. It does the repetitive work, explains its decisions, and leaves control with the person reviewing the workbook.

1

It reads the bank statement

Nordea CSV is the preferred input because it has better merchant details. Nordea PDF still works as a fallback for older statement workflows.

2

It sorts transactions

The tool uses known rules, category memory, manual review decisions, and optional local model hints to suggest where each transaction belongs.

3

It protects the workbook

It checks formulas, existing values, fixed rows, missing rows, and safe write targets before planning any workbook change.

4

It creates review files

Dry runs produce a report, CSV files, an Excel review workbook, and a detailed audit trail before commit mode is used.

5

It learns only from confirmed choices

Category Memory learns future merchant choices only when the review workbook explicitly says to learn them.

6

It keeps private data local

Real statements, real tracker workbooks, reports, backups, processed files, and learned private memory stay out of Git.

Monthly Workflow

How one month moves through the system

Think of the project as a clerk that prepares a proposal, a reviewer that asks you to confirm unclear items, and a cautious writer that only writes to a copy.

Export

You export a Nordea statement and keep it in a private ignored folder.

Dry run

The tool reads transactions and prepares a plan without changing the workbook.

Review

You inspect the report and fill in any needed choices in the review workbook.

Learn

Only selected decisions are learned for future months.

Check again

A follow-up dry run shows the effect of decisions before writing.

Commit copy

Eligible updates are written only to a copied workbook, not the original.

Product Design

The design is privacy-first, review-first, and workbook-first

This project is not trying to replace the existing tracker. It wraps the tracker with an assistant that respects how the workbook already works.

Local-first

Personal finance files stay on the machine. The project avoids bank APIs, cloud storage, telemetry, and remote model calls.

Review-first

Unclear choices go into review files. The human reviewer decides categories, new rows, and whether a choice should be learned.

Workbook-first

The Excel tracker remains the source of truth. The tool reads workbook structure and avoids overwriting formulas, manual values, or protected rows.

Audit-first

Each run explains what happened through reports and JSONL audit records, so decisions can be inspected later.

Safety Model

What the project deliberately refuses to do

The restraint is part of the design. The tool is useful because it knows when not to act.

No silent overwrite

If a target workbook cell already has a manual value or formula, the tool reports the issue instead of replacing it.

No private data in Git

Real bank statements, workbooks, reports, learned memory, backups, and processed files are excluded from version control.

No automatic LLM authority

Local model suggestions are only review hints. They do not become confirmed categories unless the review workflow confirms them.

Packaging Idea

Reusable project, personal configuration

The next grilling session should separate the shareable engine from the private personal setup. That means deciding what belongs in the public package, what belongs in a starter template, and what must remain local-only.

  • Shared engine: parsing, planning, reporting, review workbooks, validation, and safety rules.
  • Personal layer: workbook file, private bank exports, private merchant rules, proxy split amounts, and learned memory.
  • Templates: safe example categories, redacted fixtures, sample settings, and onboarding instructions.
  • Boundaries: decide whether the product is a library, a CLI template, a packaged app, or a documented starter kit.
