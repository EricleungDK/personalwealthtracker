## Technical Details

### Implementation Highlights

- Review decision validation now combines workbook category options with YAML leaf categories before rejecting reviewed `manual_category` values.
- Category Memory learning now resolves the learning target from `new_leaf_category` or `manual_category`, while retaining registry and fixed-row safeguards.
- Local Gemma planning deliberately reuses existing `suggested_category`, `method`, `confidence`, and `reason` fields to avoid widening the review workbook.

### Challenges Overcome

- Reviewed new leaf categories were valid registry targets but could be absent from the workbook before row insertion.
  - Solution: validate against YAML leaf categories as well as current workbook labels, then let workbook planning surface missing row insertion.
- Category Memory skipped reviewed `new_leaf_category` rows because only `manual_category` was imported.
  - Solution: import the reviewed new leaf as the learning target once the YAML registry validates it.
- The Local Gemma idea initially risked becoming a remote API/provider decision.
  - Solution: kept the provider local, explicit opt-in, review-only, and tied to Ollama/Gemma on the user's MacBook.

### Design Decisions

- Local Gemma suggestions remain review-only.
  - Rationale: workbook writes and Category Memory should still require confirmed review decisions.
- Provider failures fail closed to ordinary manual review.
  - Rationale: local model availability should not block monthly planning.
- `gemma4:e4b` is the first target and `gemma4:e2b` is the fallback.
  - Rationale: the user's Apple Silicon M1 with 16 GB memory should handle E4B for low-volume monthly review, with E2B available if performance is poor.
