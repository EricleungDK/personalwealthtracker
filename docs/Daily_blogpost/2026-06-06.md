## Technical Details

### Implementation Highlights
- `attempted_count` now increments inside the per-model generate wrapper, so primary failures and successful fallback retries are counted as separate provider attempts.
- `_generate_with_fallback()` now receives a model-specific callable, keeping retry logic focused while letting diagnostics count actual calls without duplicating provider invocation code.
- The prompt still includes the transaction ID as input context, but the response contract no longer requires the LLM to echo it.

### Challenges Overcome
- The fallback path already made two provider calls for one eligible row, but diagnostics counted only one eligible-row attempt.
  - Solution: added a failing regression assertion first, then moved counting to the actual generate-call boundary.
- The managed filesystem sandbox blocked Git index writes.
  - Solution: reran the Git staging and commit commands with explicit escalation.

### Design Decisions
- Keep fallback retries within the existing provider-attempt metric rather than introducing a separate retry metric.
  - Rationale: reports and audit output label the field as "Provider calls attempted", so it should match the actual provider usage count.
- Commit the Local LLM/defaults/docs/test change set together.
  - Rationale: the code, defaults, and operator documentation describe one cohesive Local LLM behavior update.
