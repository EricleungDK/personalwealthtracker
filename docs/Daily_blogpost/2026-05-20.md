## Technical Details

### Implementation Highlights

- The new plan keeps `manual_category` focused on existing Leaf Category Rows.
- New category creation is represented by separate `new_parent_category` and `new_leaf_category` review fields.
- Parent rows that allow children will come from the YAML registry rather than a hardcoded list.
- Category Memory learning is planned to validate against YAML leaf categories so it cannot learn parent rows or missing categories.

### Design Decisions

- YAML becomes the durable category registry.
  - Rationale: the user does not want the workbook and YAML to remain competing category sources.
- The reviewed second run may update YAML with validated new leaf categories.
  - Rationale: the first dry run should remain read-only, but the reviewed pass should make the category available for future runs.
- Workbook leaf row insertion stays behind planned structure changes and copied-workbook commit.
  - Rationale: workbook structure and formula edits need the same safety posture as existing workbook writes.
